# 元宝反代（Yuanbao）接入说明

> 本文档说明如何在本项目中接入「元宝反代」渠道，使其提供 `yuanbao/` 前缀的模型。

## 一、依赖说明（重要）

**本项目的元宝渠道只是一个转发入口，本身不包含任何元宝协议实现。**

- 本地 OpenAI 兼容接口来源于：**[Mao2973464622/yuanbao-openai-api](https://github.com/Mao2973464622/yuanbao-openai-api)**
  （腾讯元宝网页版 → OpenAI 兼容 API，纯 Node 协议实现，支持流式 / 多模型 / 联网 / 生图）
- 该反代服务默认监听 `http://127.0.0.1:8788`，对外提供 OpenAI 兼容的 `/v1` 接口。

> ⚠️ **必须两个项目一起使用。**
> 要正常使用 `yuanbao/*` 模型，须先自行部署并运行 [yuanbao-openai-api](https://github.com/Mao2973464622/yuanbao-openai-api)。
> 若反代未启动或端口不通，本项目的 `yuanbao/*` 模型将全部请求失败（上游不可达），其余渠道不受影响。

## 二、部署顺序

```text
1. 部署并启动 yuanbao-openai-api  →  监听 127.0.0.1:8788
2. 启动本项目（dsh-our-free-model）  →  监听 127.0.0.1:18900
3. 调用 http://127.0.0.1:18900/v1 时使用 yuanbao/<模型名>
```

验证反代是否就绪：

```bash
curl -s http://127.0.0.1:8788/v1/models
# 正常应返回 {"object":"list","data":[...]}
```

## 三、配置

| 项 | 值 |
|---|---|
| provider id | `yuanbao` |
| 显示名 | 元宝反代 Yuanbao |
| baseUrl | `http://127.0.0.1:8788/v1` |
| 协议格式 | `openai-chat` |
| API Key | `sk-local-yuanbao`（本地反代占位值，反代本身不校验） |
| 本地 | 是（`local: true`） |
| 模型前缀 | `yuanbao/` |

### 已接入模型（9 个 chat 模型）

| 模型 ID | 说明 |
|---|---|
| `yuanbao/deepseek` | DeepSeek（元宝） |
| `yuanbao/deepseek-v3` | DeepSeek V3 |
| `yuanbao/deep_seek_v3` | DeepSeek V3（别名） |
| `yuanbao/hy3` | 混元 hy3 |
| `yuanbao/hunyuan` | 腾讯混元 |
| `yuanbao/hunyuan-t1` | 混元 T1（推理） |
| `yuanbao/hunyuan_gpt_175B_0404` | 混元 GPT 175B |
| `yuanbao/hy4` | 混元 hy4 |
| `yuanbao/hunyuan_omnipotent_hy4` | 混元全能 hy4 |

> 反代实际暴露 18 个模型，另有 9 个 `-search` 联网变体（如 `deepseek-search`）。
> 如需启用联网变体，在设置中把对应模型 id 加入 `yuanbao` 渠道的模型列表即可。

## 四、手动配置方法

若未使用自动补丁，可手动写入两处：

**1. registry（代码树身份）** — `src/providers/registry.json` 追加：

```json
{
  "id": "yuanbao",
  "name": "元宝反代 Yuanbao",
  "category": "apikey",
  "auth": { "kind": "apiKey", "env": "YUANBAO_API_KEY", "url": "http://127.0.0.1:8788" },
  "baseUrl": "http://127.0.0.1:8788/v1",
  "format": "openai-chat",
  "models": [ { "id": "deepseek", "name": "DeepSeek (元宝)" } ],
  "local": true,
  "source": "custom",
  "modelsUrl": "http://127.0.0.1:8788/v1/models"
}
```

**2. settings（运行值）** — 数据目录 `settings.json` 的 `aggregate.providers.yuanbao`：

```json
{
  "enabled": true,
  "baseUrl": "http://127.0.0.1:8788/v1",
  "apiKey": "sk-local-yuanbao",
  "models": ["deepseek", "deepseek-v3", "deep_seek_v3", "hy3", "hunyuan",
             "hunyuan-t1", "hunyuan_gpt_175B_0404", "hy4", "hunyuan_omnipotent_hy4"]
}
```

改完重启本项目服务即可生效。

## 五、验证

```bash
# 1. 模型是否已出现
curl -s -H "Authorization: Bearer <你的 forwardKey>" \
  http://127.0.0.1:18900/v1/models | grep yuanbao

# 2. OpenAI 格式推理
curl -s http://127.0.0.1:18900/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的 forwardKey>" \
  -d '{"model":"yuanbao/deepseek","max_tokens":32,"messages":[{"role":"user","content":"hi"}]}'

# 3. Anthropic 格式推理
curl -s http://127.0.0.1:18900/v1/messages \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的 forwardKey>" \
  -d '{"model":"yuanbao/deepseek","max_tokens":32,"messages":[{"role":"user","content":"hi"}]}'
```

## 六、排障

| 现象 | 排查 |
|---|---|
| `yuanbao/*` 全部失败 | 先确认反代在跑：`curl http://127.0.0.1:8788/v1/models` |
| 反代端口不是 8788 | 修改 `settings.json` 里 `yuanbao.baseUrl` 的文件端口并重启 |
| 模型列表里没有 yuanbao | 检查 registry 是否有条目、settings 里 `enabled` 是否为 true |
| 上游返回 5xx | 多为元宝侧账号/额度问题，与本项目无关 |
